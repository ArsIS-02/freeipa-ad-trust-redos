# Глава 8. Тестовые пользователи для обоих доменов

Чтобы проверять доверие, HBAC, группы и детекты, нужно много учётных записей. Три скрипта из каталога
[`tools`](../tools) наполняют оба домена одним и тем же набором случайных людей:

| Скрипт | Где запускать | Что делает |
|---|---|---|
| [`gen_users.py`](../tools/gen_users.py) | где угодно, нужен только Python 3 | генерирует CSV: логины, имена, отделы, случайные пароли |
| [`import_ipa.py`](../tools/import_ipa.py) | сервер FreeIPA, после `kinit admin` | создаёт пользователей и группы отделов в IPA |
| [`Import-AdUsers.ps1`](../tools/Import-AdUsers.ps1) | контроллер домена или хост с RSAT | создаёт то же самое в Active Directory |

Один CSV грузится в оба домена, поэтому у `ivan.petrov` в IPA и AD одинаковые имя, отдел и группы. Имена
генерируются как русские (в полях ФИО, логины латиницей), так и английские: это заодно проверяет кириллицу.

> Скрипты предназначены для **лабораторных и тестовых** доменов. Не запускай их на боевом каталоге.

## 8.1. Генерация

```bash
python3 tools/gen_users.py --count 50 --out users.csv
python3 tools/gen_users.py --count 200 --lang ru --seed 42 --out users.csv
```

| Параметр | Значение |
|---|---|
| `--count` | сколько пользователей (по умолчанию 50) |
| `--lang` | `ru`, `en` или `mix`: смесь русских и английских имён (по умолчанию `mix`) |
| `--seed` | зерно, чтобы набор имён повторялся (пароли всегда случайные) |
| `--out` | выходной файл |

В CSV семь столбцов: логин, имя, фамилия, отображаемое имя, отдел, имя группы отдела и пароль.
Файл сохраняется в UTF-8 с BOM, поэтому PowerShell 5.1 корректно читает кириллицу. Отделов восемь
(бухгалтерия, продажи, ИТ, кадры, юристы, логистика, маркетинг, поддержка), группы называются `dept_buh`,
`dept_sales` и так далее.

**В CSV лежат пароли тестовых учётных записей.** Файл исключён в `.gitignore`, но проверь, что не отправляешь его
никуда, и удали после импорта.

## 8.2. Импорт в FreeIPA

```bash
kinit admin
python3 tools/import_ipa.py users.csv --dry-run     # посмотреть план
python3 tools/import_ipa.py users.csv               # создать
```

Скрипт создаёт группу-метку `lab_generated`, группы отделов и пользователей. Все пользователи входят в
`lab_generated` и в свою группу отдела. Если пользователь уже существует, он пропускается, так что запускать
повторно безопасно. Адрес почты строится как `логин@домен IPA` (изменить можно ключом `--mail-domain`).

Первый вход: пароль, заданный администратором, в FreeIPA считается истёкшим, поэтому при первом входе нужно
сразу придумать новый. Это штатное поведение.

## 8.3. Импорт в Active Directory

На контроллере домена в PowerShell:

```powershell
.\Import-AdUsers.ps1 -Domain ad.example.test -CsvPath .\users.csv -DryRun
.\Import-AdUsers.ps1 -Domain ad.example.test -CsvPath .\users.csv
```

Всё создаётся в отдельном подразделении `LabGenerated` (можно изменить `-OuName`): внутри пользователи,
группа-метка `lab_generated` и группы отделов. Пароли заданы, учётные записи включены, при первом входе нужна
смена пароля. Для запуска с другой машины или под другим администратором добавь `-Credential (Get-Credential)`.

## 8.4. Очистка

Скрипты удаляют только созданное ими.

```bash
python3 tools/import_ipa.py --cleanup --dry-run     # что будет удалено
python3 tools/import_ipa.py --cleanup               # потребует ввести yes
```
```powershell
.\Import-AdUsers.ps1 -Domain ad.example.test -Cleanup -DryRun
.\Import-AdUsers.ps1 -Domain ad.example.test -Cleanup
```

В IPA удаляются пользователи группы `lab_generated`, группы отделов, которые создал сам скрипт, и сама группа-метка.
Группы, которые уже существовали, не трогаются. В AD удаляется всё, что находится в подразделении `LabGenerated`,
и само подразделение. Удаление необратимо: сначала смотри `-DryRun`.

## 8.5. Интерактивные менеджеры доменов

Для ручной работы есть два парных скрипта с одинаковым меню из 16 пунктов. Каждый управляет **своим** доменом.

| Скрипт | Домен | Где запускать |
|---|---|---|
| [`ipa_manager.py`](../tools/ipa_manager.py) | FreeIPA | сервер IPA, после `kinit admin` (нужен ipalib) |
| [`Manage-AdDomain.ps1`](../tools/Manage-AdDomain.ps1) | Active Directory | контроллер домена или хост с RSAT; домен задаётся `-Domain` или вводится при запуске |

```bash
kinit admin
python3 tools/ipa_manager.py
```
```powershell
.\Manage-AdDomain.ps1 -Domain ad.example.test
```

Запуск: распакуй архив репозитория целиком (из окна zip скрипт не запустится), затем правой кнопкой по
`Manage-AdDomain.ps1` → «Выполнить с помощью PowerShell». Скрипт сам оставляет окно открытым, а в шапке меню показывает домен, контроллер, учётную запись с правами и сведения об АРМ и пишет причину, если
не смог стартовать. Если Windows ругается на политику выполнения или блокировку скачанного файла, выполни один раз
в PowerShell: `Get-ChildItem <папка с репозиторием> -Recurse | Unblock-File`, а при необходимости
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Скачивай файлы кнопкой Raw или архивом, а не копируй текст
через буфер: иначе потеряется BOM и кириллица превратится в кракозябры. Обычный двойной щелчок по `.ps1`
открывает его в Блокноте, а не запускает.

Меню: сведения о домене (версии, счётчики, политика паролей, контроллеры), доверительные отношения,
список и поиск пользователей, карточка, создание, удаление, отключение и включение, сброс пароля, список групп,
создание и удаление группы, участники, добавление и удаление из группы, **наполнение случайными данными**
(с предпросмотром и подтверждением) и очистка созданного. В версии для AD добавлены загрузка из CSV и смена
домена. Наполнение использует тот же набор имён, что `gen_users.py`, и те же метки `lab_generated`, поэтому очистка
из менеджера, из `import_ipa.py --cleanup` и из `Import-AdUsers.ps1 -Cleanup` совместимы.

Оба менеджера в шапке меню показывают домен, сервер или контроллер, учётную запись с правами и сведения об АРМ (имя, IP, ОС). Перед любым удалением (пользователя, группы, очистка наполнения, исключение из группы) они выводят содержимое: карточку, состав группы, полный список объектов. Удаление непустой группы и очистка требуют ввести `yes`.

## 8.6. Что произойдёт в мониторинге

Массовое создание учётных записей хорошо видно в Graylog, и это удобный способ проверить детекты:

- на DC сработают алерты на создание учётных записей (4720) и добавление в группы;
- в FreeIPA сработает алерт на изменение пользователей и групп через API.

Если алертов много, это не сбой, а ожидаемый шум одной операции. Для спокойного лога делай импорт небольшими
партиями (например, `--count 20`) или временно отключи нужные алерты в Graylog.

## 8.7. Ограничения

- Скрипты рассчитаны на связку «РЕД ОС 8, FreeIPA 4.12 и Windows Server 2025». Генератор, `--dry-run` и меню `ipa_manager.py`
  проверены локально на заглушке ipalib; PowerShell-скрипты и реальные вызовы IPA в лаборатории нужно прогнать самому. Перед массовым запуском выполни импорт на 5 пользователях.
- Имена всегда уникальны в пределах одного CSV. Если запускаешь генератор повторно с другим `--seed`, возможны
  совпадения логинов с уже созданными: такие записи будут пропущены с пометкой «уже существовало».
- Максимум уникальных ФИО ограничен списками имён и фамилий. Если запросишь слишком много, генератор подскажет.
